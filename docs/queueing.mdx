## First in, first out

Each `show*` call adds a koast to the back of a queue. The koast at the front is the only one that counts down its duration and responds to swipes and clicks. When it leaves, the next koast takes its place.

```kotlin
koastManager.show("Uploading", "1 of 3")
koastManager.show("Uploading", "2 of 3")   // waits for the first
koastManager.show("Uploading", "3 of 3")   // waits for the second

koastManager.queue            // pending koasts, front first
koastManager.currentKoast     // the koast in front, or null
koastManager.isShowing        // whether anything is queued
```

How the waiting koasts are drawn depends on the [display mode](/display-modes).

### One lane per position

The queue is split by position: every koast goes to its [style's](/per-koast-styles) `position`, or to the host config's position if it has none. Each position is its own first-in, first-out lane with its own front koast, so a toast at the bottom doesn't wait for a banner at the top. `dismiss()` removes the oldest koast overall, which is the front of its lane.

## Updating a koast with a key

Pass a `key` to update a koast instead of queueing another one. If a koast with the same key is still showing or waiting, the new one replaces it in place:

- it keeps the same queue position and the same id;
- its title, message, lifetime, style and click behavior come from the new call;
- its duration starts over.

```kotlin
koastManager.showPersistent("Uploading", "0%", key = "upload")
koastManager.showPersistent("Uploading", "40%", key = "upload")   // updates the same koast
koastManager.show("Upload complete", key = "upload")              // replaces it, then times out
```

A koast on screen updates its text without leaving and coming back, which suits progress and status messages.

Every `show*` method accepts `key`. Koasts with different keys, or with no key, queue as usual. Once a keyed koast is gone, the next call with that key queues a fresh koast with a new id.
